# MVP 게이트 — 구현 전 심사

아래 5문항에 **모두 서면으로 답한 뒤에만** 구현을 시작한다. 하나라도 "아니오"거나 답할 수 없으면 구현하지 말고 창업자에게 되묻는다.

1. **세 동작 매핑**: 이 작업은 ①지시하기 ②답변 받기 ③수행됨 처리 중 무엇을 강화하는가? 어느 것도 아니면 → ROADMAP 제안 문안을 쓰고 멈춘다.
2. **일의 전후**: 이 변경 후에도 상대방이 보는 구조(메일·직답 페이지)와 우리가 기대하는 답의 구조가 일치하는가?
3. **입구 검사**: 지시 생성 입구가 늘어나는가? (`/capture` 하나여야 한다 — 늘면 통합안을 먼저 제시)
4. **불가침 검사**: 서버가 사용자의 메일함·구글 토큰에 접근하게 되는가? (send 단독 원칙 — 위반이면 브라우저-로컬 대안을 설계)
5. **시점 검사**: 이 기능 없이도 도그푸딩 지표(직답 응답률·2주 지시자 잔존율)를 잴 수 있는가? 잴 수 있다면, 왜 지금 만들어야 하는지 한 줄로.

## 출력 형식

```
[MVP 게이트]
1. 동작: ②답변 받기 — (근거 한 줄)
2. 전후: 일치 / 불일치(→수정안)
3. 입구: 불변 / 증가(→통합안)
4. 불가침: 통과 / 위반(→대안)
5. 시점: 지금 (근거) / 보류
판정: 진행 | 보류(ROADMAP 문안: "…")
```

판정이 "진행"이면 그대로 구현에 들어가고, "보류"면 ROADMAP 문안과 함께 창업자에게 보고한다.
